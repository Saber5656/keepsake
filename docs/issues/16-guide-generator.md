# Title

Printable HTML guide generator with QR codes (`keepsake guide`)

## Summary

Implement `internal/guide` + the `guide` command: generate the two self-contained printable HTML artifacts — recipient guide (Japanese, with share_R QR and anti-phishing CHECK) and owner Recovery Sheet (passphrase + QR) — from config, seal-manifest, and the content pack.

## Context

Paper is the recipient's primary interface (DESIGN §2.2, §14) and the anti-phishing CHECK group's distribution channel (§10.5 A7). Files must be fully offline-rendable (inline CSS, data-URI images) and print correctly on A4.

## Scope

- `internal/guide/guide.go`, `qr.go`, `templates/*.gohtml` (+ tests), command wiring.
- QR library selection between `github.com/skip2/go-qrcode` and `github.com/yeqown/go-qrcode/v2` (KU-3): evaluate print quality at 300dpi-equivalent size and maintenance status; record the choice + rationale in the PR and add the dep to the allowlist table.

## Detailed Requirements

1. `Generate(cfg, sealManifest, contentFS) (recipientHTML, ownerHTML []byte, err error)` + command writing to `out/guides/` (atomic).
2. Recipient guide content (copy from 09 with placeholders filled): all sections listed in issue 09 req 2; embeds — share_R QR (data-URI PNG ≥ 480px logical, EC level M) + share_R full text in monospace groups; share_G CHECK group prominently boxed (「本物のメールの確認コード」); owner name; seal date; guide_version.
3. Recovery Sheet: passphrase QR + text, `age -d kit.age` steps, storage warnings (verbatim from 09), print/rotation date lines.
4. HTML constraints: single file, no external requests (CSP meta `default-src 'none'; img-src data:; style-src 'unsafe-inline'`), A4 print CSS (`@page`, page-break rules so each major section starts cleanly), system font stack with Japanese fallbacks (`"Hiragino Sans", "Yu Gothic", "Noto Sans CJK JP", sans-serif`) — KU-4 noted in file comment.
5. Templating: `html/template` only (auto-escaping); placeholder contract from `internal/content/PLACEHOLDERS.md` — build fails a test if any placeholder is unfilled or unknown.
6. Secrets discipline: Recovery Sheet is the ONLY artifact ever containing the passphrase; command prints a red-flag notice before writing it and requires confirm (or `--yes`); recipient guide must never contain passphrase or share_G (test greps rendered output for those exact strings from the fixture).
7. Both artifacts contain "generated by keepsake <version> on <date>" footer and kit fingerprint for correlation.

## Acceptance Criteria

- [ ] Golden-render tests with fixture data (stable except date/version fields, which are injected).
- [ ] QR decodes back to exact sharetext via a Go QR-decode dev-dependency in tests.
- [ ] Placeholder completeness test wired to PLACEHOLDERS.md.
- [ ] Secret-leak grep tests (recipient guide clean; Recovery Sheet contains passphrase exactly once).
- [ ] Manual print QA: A4 PDF export from Chrome + Safari attached to PR; QR scans from paper with a phone (owner confirms).

## Validation

CI golden + QR round-trip tests; human print/scan QA recorded in PR (this is the KU-3/KU-4 gate).

## Dependencies

09, 13 (seal-manifest as input; CHECK groups).

## Non-goals

PDF generation (browser print is the v1 path), mail bodies (21), multi-language guides (v2), photos/screenshots in guide (v2).

DESIGN §7 (QR), §8 (guide row), §10.5 A7, §14; ISSUE_PLAN KU-3/KU-4.
